# 將郵件移至垃圾桶

## 目標

讓使用者直接將已選定的郵件移至郵件服務的垃圾桶，省去先移到暫存資料夾再手動刪除的步驟。郵件可在服務商的保留期限內透過原郵件客戶端復原。

## 實作

1. 新增 `trash_email` 和 `trash_emails_batch`。兩者使用現有完整郵件識別資料。批次接受同一帳戶的 1–50 個唯一識別資料，按輸入順序回報逐封結果。
2. Broker 從同一 IMAP 工作階段的 `LIST` 結果解析唯一且可選取的 `\Trash` 信箱。批次在首次寫入前解析一次。使用原生 `UID MOVE`，並沿用來源信箱、`UIDVALIDITY` 和 UID 驗證。缺少原生 `MOVE` 能力或可信目的地時，在寫入前結束。
3. 沿用移動結果格式，回傳目的地信箱及可取得的 `COPYUID` 映射。批次允許逐封部分成功。若寫入期間失去連線或逾時，回報結果不明並停止其餘寫入。重試前先核對兩個信箱。
4. 維持一般移動工具的特殊用途信箱限制。更新代理操作指引，要求寫入前確認帳戶、來源、郵件識別資料及封數。Broker 按郵件記錄結果與目的地，並更新 IPC 版本、契約與工具結構的固定摘要。

## 驗收

- 驗證單封成功及批次部分成功、順序和稽核紀錄。
- 驗證缺少、不唯一或不可選取的垃圾桶、來源限制、缺少 `MOVE`、重複識別資料、跨帳戶及過期的 `UIDVALIDITY`。
- 模擬寫入期間連線中斷，確認回報不確定結果及停止其餘項目。驗證 MCP 和 IPC 均不接受自訂垃圾桶目的地。
- 執行自動檢查並由 Astra（medium）子代理進行最終程式碼審查。
